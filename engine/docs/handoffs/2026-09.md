## Gotchas that bite now

- **A FIB `ip route get … from <addr>` probe must never source from the probing host's own
  address** — it is a martian source (EINVAL) on every kernel regardless of policy (LES-355). This
  cost real diagnosis time reading it as "the assertion doesn't work here" when the policy was
  correct the whole time.
- **A fire-and-forget mirror/tunnel must set `nopmtudisc ignore-df`, never rely on PMTU
  discovery** (LES-356) — a mirror has no sender to receive the ICMP frag-needed, so an oversized
  frame is dropped with zero signal anywhere. The fix does not retroactively heal a standing tap
  (see svc-engines above) — it only takes effect on the next apply.
- **A traffic driver renders for the persona's declared `os_family`, never the host's actual OS**
  (LES-354) — `tfc validate|plan|deploy` now refuse a mismatch, but only a repo-wide test sweep or
  a live validate catches a NEW one; not a schema-level guarantee.
- **GAP-101 is RESOLVED** (landed 2026-09-23, `6b8cc50b`) — `egress:` IS authorable in a twin
  config now. Check `docs/PRODUCT_GAPS.md` GAP-101 before assuming otherwise. **GAP-100 is still
  open** — the any-IP sink receives an external SYN but never answers it.
- **A twin's `egress:` must be set (or defaults to `measure`) before trusted for containment** —
  the gate probes the router LIVE every deploy attempt (LES-348); an unphased router needs
  `--allow-uncontained`, a loud, named exception, never silent.
- **Never redeploy a devlab/corp-twin guest that failed mid-provision without destroying first** —
  half-applied state does not reconcile against a resumed plan. **Unquoted heredoc backticks run
  as commands even in prose comments** (LES-351, `tests/test_twin_recipe_heredocs.py` now catches
  this repo-wide). **`apt-daily-upgrade.timer` fires within minutes of a fresh boot** and can
  orphan a mid-flight QGA exec (LES-353) — quiesce it before the first package step in any new
  recipe.
- **Install before repointing DNS** on any twin with its own name service — once a guest resolves
  through the twin resolver it has no upstream, and `apt` fails silently as "a broken mirror."
- **The standing O2 suricata sensor recurred dead again (GAP-067)** — silent since 2026-07-27;
  `o2 status: present` does not mean it is capturing (LES-247). **`:8080`** (tmux `axrange-serve`)
  — confirm PID/build hash before trusting it; never build into `o2/console/dist` while it serves
  (LES-315); never point a browser probe at `twin-configs-cast/` — copy to scratch first (LES-338).
  Console gate: `cd o2/console && npm ci && npm run typecheck && npm run test` (node ≥ 22.12).

### Mental model / gotchas

**Console-specific (new this session):**

- **`AXRANGE_DEV_API` and `VITE_AXRANGE_API` are not interchangeable.** The first is read by
  `vite.config.ts` at config time and sets the **dev proxy's target**, never reaching the browser;
  the second is **compiled into the bundle** as an absolute base URL that bypasses the proxy and
  needs CORS the API does not implement. They were one variable at first, which was a bug — Vite's
  `loadEnv` lifts every `VITE_`-prefixed variable into the client (LES-252).
- **An etag from a 412 is for a reload, never a retry** (LES-251). Adopting it inverts the guard:
  the retry succeeds, the other writer's change is gone, and every concurrency test still passes.
- **A history fallback makes every miss look like a 200** (LES-257) — so `/api/` is excluded on the
  **decoded** path (`%61pi` too), assets are an **extension allow-list** (the Console's own routes
  are full of dots), and a traversal test can only be written as "the sibling file's content is
  **absent** from the body", never as "expect 404".
- **The cache policy is two lines or the app boots blank after a rebuild** (LES-256): the index
  `no-cache`, `/assets/` immutable.
- **The Python↔TypeScript DTO mirror is hand-written** (LES-258). Its guard runs on the **Python**
  side and names `o2/console/src/api/types.ts` when it fails; it proves field **names**, not values,
  and only what existed when it was written. The live-API test (`AXRANGE_LIVE_API`) is the value
  half and is skipped by default.
- **The write token lives in memory for the life of the tab** — never compiled in, never in storage;
  a reload drops it. A bundle grep proves it.
- **The dev server binds `127.0.0.1` explicitly** — Vite 8 defaults to `localhost`, which resolves
  to `[::1]` on this host, so `curl http://127.0.0.1:5173` failed while a browser worked.

**Carried forward, still true:**

- **The apply is a two-stage pipeline and the first stage alone updates nothing.** `aximprint cast`
  writes **generic file stems** into a scratch directory; only `install-cast` names them `<id>.*`
  in the catalog. A guard keyed on `<id>.yaml` existing reports success for a stage that did nothing
  (LES-232).
- **`code_fingerprint` is a BUILD hash, not a content identity.** Two different casts of the same
  compiler share it. Change detection is axRange's own sha256 over the bundle's three files
  (LES-232), and a build's **invocation** is part of its identity — a bundle with no
  `cast_invocation` is refused by name, never recompiled with guessed flags (LES-237).
- **The assertions vocabulary is vendored, not restated.** `axrange/api/schemas/` holds a
  byte-identical copy of aximprint's schema; the closed sets are derived from it at import; the
  drift test skips cleanly when the sibling repo is absent. **Do not edit the vendored file** —
  axRange's own extra rules live in code with their reasons (LES-230).
- **A fake backend can hide the bug it stands in for.** Put the seam at the process boundary and run
  the real tool once before calling a cross-process feature done (LES-242, LES-208).
- **For a sensor, "exists" is not the check.** *Exists, running, and fresh* is — `o2 status` cannot
  tell a dead capture from a live one, and the standing `o2-suricata` proved it for 40 days
  (LES-247, GAP-067). Check `eve.json`'s newest record before trusting any capture claim.

  live twin DB is `~/.axrange/state.db`; `deploy-dev45/state.db` in this repo is a **stale June

  `deploy-dev45` root has every twin binding and **no** `suricata-sensor`; the `axr-product` root
  has it. A missing binding is silent at plan time and fails on the cluster **after** SDN ops ran.
