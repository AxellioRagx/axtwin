# aximprint

Orientation for Claude Code. This file is a **summary of `docs/`** — never a contradiction. The design of record is `docs/DESIGN_BRIEF_aximprint.md`; the house rules are `docs/CONVENTIONS.md`; the working modes are `docs/WORKFLOW.md`.

## What this project is

Ingest continuous network metadata produced by a **sensor** (Zeek first; Suricata and packetXpress later), **discover the network** — hosts, topology, services, endpoint behavior — persist that knowledge as a temporal belief store, and **cast** a snapshot of it into deployable digital-twin configuration for the sibling project **axrange** (`twin_config` + `tfc` traffic profile + `tap` plan).

```
sensor metadata → [ingest plugin] → normalize → window/features
      → learners → belief store ── snapshot as-of T ──> synthesizer
      → twin_config + tfc profile + tap plan  ──> axrange deploys the twin
```

Two framing decisions were ratified up front (DESIGN_BRIEF §0), and they explain most of the code's shape:

1. **The discovery pipeline is NOT a sensor and never sees a packet.** Sensors produce metadata; a per-sensor **ingest plugin** normalizes it. Capture-layer concerns (NIC tuning, dedup, drop accounting) belong to the sensor — the pipeline only requires that the plugin surface sensor health so window completeness stays honest. **Amended 2026-08-10 (user):** this used to say *aximprint owns no capture path* — a claim about the repo. That claim is now false at the repo level: `xtract` (formerly `../xapi-pcap-extract`) has **merged in as `src/aximprint/acquire/`** (CHANGELOG 2026-08-10, `docs/WORK_ORDER_merge_xtract_acquire.md`), so the repo owns a capture path and handles packets. The property that mattered is a layering rule instead of an accident of packaging: **`acquire` must not import `events`**, checked by an AST-walk test (CONVENTIONS §3), not just stated. Zeek is still a stopgap; the event model is still the only thing stable when Xpress replaces it, and one repo does not make that boundary negotiable.
2. **No schema is versioned yet — amended 2026-08-14 (user): exactly one now is** (at `1.3` since 2026-08-27; the version has moved four times, the scope not once). The event model, feature shapes, plugin contract, and belief-store shapes remain **incubating** and change freely; do not add version fields, bump ceremonies, or compatibility shims to any of them (`LES-001`). What changed is that the **network IR** (`docs/WORK_ORDER_network_ir.md`) is **ratified as a versioned schema** — the first, and so far only, §0.2 ratification this project has made. **Read the scope narrowly, because reading it broadly is precisely the `LES-001` failure:** the IR is versioned *because* it crosses a boundary — a persisted, point-in-time artifact that a drift comparator, a diagram generator, a GNN evaluation harness and the twin compiler all read. The belief store stays free *because* it stays internal. That asymmetry is the design, not a transitional state, and "one schema is versioned" is not a step toward versioning the rest.

Central metaphor: the network leaves an **imprint** in its traffic; the synthesizer **casts** it into a runnable replica. The metaphor lives in prose and UX, not in identifiers (CONVENTIONS §5).

## Conventions to follow

> **The house rules live in `docs/CONVENTIONS.md`** — doc taxonomy (§2), engineering rules (§3), pipeline route (§4), naming (§5). The four that bind every change:

- **Layering imports downward only.** `ingest`→`events`, `windowing`→`events`, `learners`→windowing outputs, the output-sink layer (`sinks` + `features`, split — CONVENTIONS §3)→windowing outputs + `events` (imported only by the CLI), `store`←writers, `synth`→reads store. No upward imports. **`acquire`→nothing** — the acquisition package (landed 2026-08-10 from `xtract`) produces sensor artifacts on disk and must not import `events`; the CLI wires it to `ingest` and neither imports the other. **Checked, not just stated**: an AST-walk test (CONVENTIONS §3), mutation-proven.
- **Determinism as a feature.** Window close is a pure function of (events, resolver state, code build) — §5.4. The synthesizer is a deterministic compiler — §9. Seeded randomness everywhere it exists; byte-stable outputs. Nothing wall-clock, unseeded, or set-iteration-ordered may reach an output. `scripts/verify_determinism.py` is the check; `LES-002` is why.
- **Fail loud, fail closed.** Guards are positive gates; an unrecognized shape is rejected, not passed through. Assertions over silent defaults.
- **Provenance everywhere.** Every assertion carries `evidence_class` (`observed` / `referenced` / `imputed`), confidence, source, and time bounds. **Imputed never masquerades as observed** — it propagates into the synthesized config's provenance and is the project's central honesty claim.
- **Forensic completeness — collect everything, redact nothing.** **Ratified 2026-08-12 by the user, superseding the former Privacy rule** (CHANGELOG 2026-08-12; CONVENTIONS §3, DESIGN_BRIEF §7). aximprint collects **every field it observes** — cleartext credentials, usernames, filenames, mail recipients, SIP extensions, LDAP directory names — and declines nothing on disclosure grounds. It records facts; **`axrange` owns the disclosure decision.** The engineering reason: a field withheld at collection time is indistinguishable downstream from one never observed, which attacks the provenance claim above. Do **not** add a redaction, a privacy-motivated field refusal, or a "narrow set" comment to a parser. Two things unaffected, neither being a disclosure judgment: **cardinality bounds stay** (`MAX_KEYS`/`SERVICE_MAX_KEYS`/`TOP_PEERS` are store economics — `LES-017`, `Q9`; truncation always disclosed), and **run data still stays out of the repo** (`LES-003`, now repo hygiene, not privacy — same reason a 9 GB pcap is not committed).
- **Content vs code.** Catalogs and templates are data files, not code.

## Working modes

One always-on baseline plus two optional modes; full model in `docs/WORKFLOW.md`.

**Baseline** (no machinery behind it): docs are the source of truth; every decision carries a CHANGELOG `**Authority:**` marker; **`docs/SESSION_STATE.md` is the cross-session handoff** — a committed file, read it at session start and update it at wrap; the user reviews every diff. Mid-flight work goes on an ordinary branch, named in that file.

- **Pipeline** (optional) — `/dev <task>` runs code-writer → tester → code-reviewer → doc-writer → (gated) live-verifier in the background, checking back only on a decision or a gate.
- **Chat-bridge** (optional) — `./scripts/claude-export.sh` / `claude-import.sh` ferry a design question to a Claude chat session and back through a reviewed tarball.

**Mechanism is host-global, policy is per-repo** (workflow v7). The five agents, `/dev`, and the hooks live in `~/.claude/`, symlinked into the template clone, so a template fix reaches every project at once — **do not add a `hooks` block to `.claude/settings.json`**, it would register every hook twice. What stays here, reviewable in this repo's history: `.claude/settings.json` (the permission allowlist), `.claude-workflow.env` (including `CLAUDE_VERIFY_STEPS` and `CLAUDE_WORKFLOW_VERSION`), `docs/LESSONS.md`, and `scripts/verify_pipeline_gates.sh`.

## Design authority and the risk gate

Design and implementation both happen here; **there is no authority split by surface** (CONVENTIONS §1.1). Claude Code advances design by default and records it. Every CHANGELOG entry carries an `**Authority:**` marker; a reversal carries `**Supersedes:**`. The record is the safety net, not a pre-flight gate.

**Confirm with the user first only when a change would:**

- reverse a ratified decision in `docs/CHANGELOG.md` or the design brief,
- **ratify a schema** — add version fields, a bump ceremony, or compatibility shims (DESIGN_BRIEF §0.2; §11 is inert design capture until then),
- add a runtime dependency (deliberately thin: `duckdb`, `pyyaml`), or
- shift the scope or direction of the current iteration.

**Not a gate:** *changing* the event model, feature shapes, plugin contract, or belief-store schema. Those change freely during incubation. This inverts the axRange rule and is the habit most likely to leak across from the sibling project (`LES-001`).

Also gated at the harness level (`.claude/settings.json`): `aximprint ingest`/`synth`, any `axrange` verb, `git commit`/`push`/`tag`, dependency installs, and — since the 2026-08-10 `acquire` merge — `aximprint acquire pcap`/`aximprint acquire harvest` and `podman`. **Rationale restated 2026-08-12**, since privacy no longer supplies it: `pcap`/`harvest` reach a **live production appliance** and pull multi-GB onto this host — cost and blast radius, not disclosure. Merely *reading* a capture or a store derived from one is **no longer gated in spirit** (it never was in `settings.json` — `cat`/`head`/`ls` are allowlisted); the earlier version of this line claimed otherwise and was wrong even then. `aximprint acquire streams` is read-only catalog reporting and is deliberately **not** gated, same tier as `status`. **The permission lists themselves are unchanged by this ratification** — retuning them is a separate call.

## Git policy

Remote is `origin`. **Outbound push is user-authorized per request; inbound sync stays manual** — `git fetch`/`pull`/`clone` and remote reconfiguration are denied. If asked to pull or fetch: *"Inbound remote sync is your manual responsibility."*

Commit style `type: subject` — kind (`feat`/`fix`/`docs`/`design`/`refactor`/`test`/`chore`) or area (`ingest`/`windowing`/`learners`/`store`/`synth`/`cli`/`workflow`/`acquire`).

Doc-counter drift is **hard-blocked at `git commit`** by a hook. Run `python scripts/doc-stats.py --check` and reconcile before committing.
